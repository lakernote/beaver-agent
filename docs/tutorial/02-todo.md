# 学习：任务规划（todo_write）

对应源码：`internal/builtin/tools/todo.go`，提示词规则 7 在 `internal/builtin/prompt/system.md`。

## 1. 为什么需要

没有规划时，模型靠“边走边想”完成多步任务：步骤一多就容易漏项、重复、忘了做到哪。
解决办法很朴素：**让模型先把步骤写下来，做完一步就更新一次。** 写下来的清单留在对话里，下一轮模型一眼就能看到进度。

## 2. 最小实现：无状态工具

`todo_write` 没有数据库、没有内存状态：

1. 模型每次提交**完整清单**（覆盖上一次），每项 `content` + `status`（`pending` / `in_progress` / `completed`）；
2. 工具只做校验（1–20 项、不超长、最多一项 `in_progress`），然后把清单格式化回显：`1. [x] 读代码`、`2. [~] 改实现`、`3. [ ] 跑测试`；
3. 回显作为 `tool` 消息进入历史，**清单就存在对话历史（和 Trace）里**。

这再次说明：Agent 的“能力”往往不是新增机制，而是一个普通 Tool 加一条提示词规则。校验失败返回错误，模型会按提示修正后重试。

## 3. 何时用

提示词规则 7 只给原则：需要 3 步以上的复杂任务才用，一两步能完成的不要用。代码里没有“检测到复杂任务”的关键词判断——是否规划由模型决定，这是本项目一贯的边界（见 `design.md`）。

## 4. 练习

1. 运行 `go test ./internal/builtin/tools -run Todo -v`，读懂每个校验分支。
2. 给 `todo_write` 加一条规则：`completed` 不能回退成 `pending`。要做到这点必须有状态——想想状态放哪里最简单？（提示：这正是无状态设计省掉的复杂度。）
3. 在 Web 里发一个“读完 docs 目录并总结”的任务，打开 Trace，观察清单如何被逐步更新。
